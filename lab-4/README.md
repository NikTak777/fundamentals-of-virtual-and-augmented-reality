# Лабораторная работа №4 Учебный стенд с дополненной реальностью

Страница распознаёт маркер Hiro через камеру и показывает над ним две
шестерёнки. Кнопка «Пуск / Стоп» управляет вращением. Когда маркер исчезает
из кадра, модель скрывается и движение приостанавливается. После повторного
обнаружения маркера работа продолжается с сохранённого положения.

Это демонстрационная модель передачи 1:1. Прямоугольные зубья и заданное
вращение упрощены: физического расчёта столкновений, нагрузки и трения нет.

в основном `index.html` и `app.js`; большие файлы в `vendor` написаны авторами
библиотек и подключаются готовыми.

## Запуск на компьютере

Нужны Python 3.8 или новее, браузер Chrome либо Edge и веб-камера.

1. Открой папку `lab4-ar` и дважды нажми `start.bat`.
2. Оставь открытым появившееся окно сервера.
3. В браузере открой **http://localhost:8000**.
4. Разреши сайту использовать камеру.
5. Открой **http://localhost:8000/marker.html** и распечатай маркер. Можно
   показать его на телефоне или другом экране вместо печати.
6. Покажи маркер веб-камере. Его рамка должна целиком попадать в кадр.
7. Когда появится сообщение «Маркер найден», нажми «Пуск».
8. Проверь остановку кнопкой «Стоп» и скрытие модели при убирании маркера.

Локально интернет не нужен: все файлы загружаются из этой папки.
Обычное открытие `index.html` двойным щелчком не подходит — нужен сервер.
Остановить его можно сочетанием Ctrl+C в окне сервера.

Если предпочитаешь терминал, открой его в папке `lab4-ar` и выполни:

```powershell
py -3 serve.py
```

Если команда `py` отсутствует, попробуй `python serve.py` или выбери файл
`serve.py` в PyCharm и нажми Run. Если Python не найден ни одним способом,
установи его с https://www.python.org/downloads/ либо используй путь к уже
установленному интерпретатору. В `start.bat` сначала проверяется `py`, затем
используется команда `python`.

Если порт 8000 занят:

```powershell
py -3 serve.py --port 8001
```

Тогда страница будет доступна по адресу **http://localhost:8001**.

## Запуск на смартфоне

Для демонстрации по варианту методички с наведением смартфона понадобится
открыть страницу на самом телефоне. Практический вариант — GitHub Pages:
он предоставляет сайту HTTPS, необходимый для доступа к камере.
В этом случае Python на телефоне не нужен.

1. На GitHub создай публичный репозиторий, например `lab4-ar`.
2. Через **Add file → Upload files** загрузи **содержимое папки `lab4-ar`**.
   Файл `index.html` должен оказаться прямо в корне репозитория, а `assets`
   и `vendor` — остаться папками рядом с ним. Подтверди загрузку кнопкой
   **Commit changes**. Если в новом пустом репозитории нет кнопки Add file,
   используй ссылку **uploading an existing file**.
3. Открой **Settings → Pages**.
4. В разделе **Build and deployment** выбери **Deploy from a branch**,
   ветку `main`, папку **/(root)** и нажми **Save**.
5. Дождись успешной публикации. Ссылка появится на этой же странице;
   обычно она имеет вид `https://ТВОЙ-ЛОГИН.github.io/lab4-ar/`.
6. Открой эту ссылку на смартфоне в Chrome на Android или Safari на iPhone.
   Разреши доступ к камере.
7. Распечатай маркер либо открой страницу `marker.html` этого сайта на
   компьютере. Наведи на него смартфон и нажми «Пуск».

Локальный адрес компьютера `http://192.168...` не заменяет HTTPS:
браузер телефона обычно не разрешает камеру при таком подключении.
Сам `serve.py` слушает только компьютер, на котором он запущен.
Адрес `localhost` на телефоне означает сам телефон, а не твой компьютер.

Для GitHub Pages интернет нужен. Для проверки с веб-камерой компьютера
достаточно локального сервера. Не удаляй `vendor` и `assets` при публикации.

## Что объяснить по коду на защите

### Как устроено приложение

1. `index.html` подключает A-Frame, затем AR.js, затем собственный `app.js`.
2. В `app.js` регистрируется компонент `gear`, который создаёт шестерёнку.
3. Скрипт проверяет возможность обращения к камере и вставляет шаблон сцены
   из `index.html` в документ.
4. AR.js получает изображение камеры, ищет шаблон `assets/patt.hiro` и
   определяет положение маркера. Готовая библиотека выполняет этот алгоритм.
5. Дочерние объекты `a-marker` получают положение относительно найденного
   маркера. Поэтому подставка и колёса перемещаются вслед за карточкой.
6. События `markerFound` и `markerLost` изменяют состояние интерфейса.
7. Метод `tick` компонента `gear` изменяет угол каждого колеса, когда запущено движение
   и маркер находится в кадре.

### Основные конструкции

| Конструкция | Для чего нужна |
|---|---|
| `a-scene` | Содержит 3D-сцену и настройки AR.js |
| `a-marker` | Привязывает свои дочерние объекты к найденному маркеру |
| `a-entity` | Группирует части колеса: они вращаются вместе |
| `a-cylinder` | Диск колеса и его центральная ось |
| `a-box` | Подставка, зубья и светлая отметка на колесе |
| `AFRAME.registerComponent('gear', ...)` | Регистрирует собственный компонент создания колеса |
| `init` | Создаёт геометрию один раз при инициализации компонента |
| `running` | Показывает, нажата ли кнопка «Пуск» |
| `markerVisible` | Показывает, найден ли маркер в текущий момент |
| `tick(time, timeDelta)` | A-Frame вызывает этот метод перед отрисовкой каждого кадра |
| `speed` | Скорость колеса в градусах в секунду: 30 для левого, -30 для правого |
| `object3D.rotation.y` | Угол поворота вокруг вертикальной оси в радианах |

### Как строится шестерёнка

Основу образует цилиндр. Цикл `for` создаёт 12 зубьев через 30°.
Координаты каждого зуба рассчитываются по окружности:

```javascript
x = Math.cos(angle) * 0.2925;
z = Math.sin(angle) * 0.2925;
```

Здесь `angle = i * 2 * Math.PI / 12`, а `0.2925` — расстояние от центра
колеса до центра зуба. По оси Y задаётся высота, поэтому зубья расположены
в плоскости XZ. Отдельный поворот каждого зуба разворачивает его вдоль радиуса.
Параметры `position`, `width`, `height`, `depth`, `radius` заданы в координатах
сцены относительно маркера; для работы не требуется измерять их линейкой.

### Почему колёса вращаются с одинаковой скоростью

Оба колеса одинаковые и имеют по 12 зубьев. Передаточное отношение — 1:1.
Компонент `gear` выполняет один и тот же код для обоих колёс, но получает
разную скорость: `30` для левого, `-30` для правого. В каждом кадре:

```javascript
const seconds = Math.min(timeDelta / 1000, 0.05);
this.el.object3D.rotation.y += this.data.speed * Math.PI / 180 * seconds;
this.el.object3D.updateMatrix();
```

Умножение на `Math.PI / 180` переводит градусы в радианы, а умножение на
`seconds` учитывает время кадра. Ограничение шага до 0,05 секунды
предотвращает скачок при возвращении на вкладку; после долгой паузы время
анимации намеренно не догоняет прошедшее время. Правое колесо изначально
повёрнуто на 15° — половину углового шага зубьев, чтобы зубья попадали в промежутки.

`updateMatrix()` сразу применяет новый угол к матрице объекта для отрисовки.
Отдельного цикла `requestAnimationFrame` в собственном коде больше нет:
анимация выполняется в общем цикле отрисовки A-Frame.

В мобильной разметке элемент `html` закреплён по размеру экрана. Это предотвращает
разрастание области страницы при масштабировании видео библиотекой AR.js.
Слой 3D-сцены не перехватывает касания: в этой работе управление выполняется
обычной кнопкой поверх сцены.

### Короткие ответы на возможные вопросы

- **Где алгоритм распознавания?** В готовой библиотеке AR.js. Собственный
  код задаёт шаблон маркера и реагирует на результат распознавания.
- **Чем занимаются HTML, CSS и JavaScript?** HTML задаёт интерфейс и сцену,
  CSS — оформление, JavaScript — геометрию, события и движение.
- **Зачем нужны два файла Hiro?** PNG нужен человеку для печати; `patt.hiro`
  содержит числовой шаблон, с которым библиотека сравнивает изображение.
- **Почему это AR?** Модель накладывается на живое изображение камеры и
  сохраняет положение относительно реальной карточки.
- **Почему модель исчезает?** Когда маркер не найден, AR.js скрывает его
  дочерние объекты. Наш код дополнительно приостанавливает вращение.
- **Это физическая симуляция?** Это визуальная демонстрация: оба угла
  изменяются программно, контакт зубьев физическим движком не рассчитывается.
- **Для чего Python?** Только чтобы раздавать файлы локально. Распознавание
  и отображение выполняются в браузере; на GitHub Pages Python не используется.

## Если что-то не работает

| Ситуация | Что проверить |
|---|---|
| Ошибка доступа к камере | Разрешить камеру для сайта, закрыть программы с камерой, обновить страницу |
| На смартфоне нет камеры | Открыть сайт по HTTPS во внешнем браузере, а не внутри мессенджера |
| Камера включена, но модель не видна | Показать именно Hiro целиком, включая чёрную рамку и белое поле |
| Маркер плохо распознаётся | Убрать блики, улучшить освещение, держать карточку ровно и не слишком близко |
| Колёса выходят за края экрана | Отодвинуть смартфон от маркера, пока модель не поместится целиком |
| Кнопка «Пуск» неактивна | Сначала дождаться сообщения «Маркер найден» |
| Пишет, что не загрузились библиотеки | Убедиться, что папка `vendor` лежит рядом с `index.html` |
| GitHub Pages показывает 404 | Проверить корень репозитория, настройки Pages и завершение публикации |

## Что показать при сдаче

Показать обнаружение маркера смартфоном, привязку модели при перемещении
карточки, запуск и остановку колёс, исчезновение модели после убирания
маркера. Для отчёта сохранить скриншоты и описать выбранный сценарий.

Эта папка закрывает практическую реализацию. Сравнительный анализ систем,
3–4 сценария и сам отчёт остаются отдельными частями задания.
